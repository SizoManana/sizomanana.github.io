PINE: a faster first pass, with the consultant still accountable.

Personal Intelligence Engine is a local working prototype designed to turn a lengthy first-pass website audit into a faster, structured starting point for consultant review.

The premise is intentionally narrow: AI performs the first pass. The consultant supplies context, verification, prioritisation and accountability.

The challenge

A day-long first pass should not delay the first useful conversation.

PINE began as a practical response to repetitive prospect and upselling audits. The opportunity was not to automate consulting judgement. It was to reduce repetitive inspection work, surface likely issues quickly and give the consultant a clearer place to begin.

What I wanted the tool to do

  • Accelerate prospect and upselling preparation
  • Combine visual inspection with structured CRO reasoning
  • Produce prioritised findings a consultant can verify
  • Make the limits of AI visible rather than hide them

What I did not want it to become

  • An autonomous UX researcher
  • A source of unverified conversion claims
  • A compliance checker pretending certainty
  • A replacement for analytics, testing or consultant judgement
Core product positionAI performs the first pass. The consultant supplies context, verification, prioritisation and accountability.

How PINE works

Two modes. Five stages. One consultant-controlled output.

The prototype offers a Full CRO Audit and a more focused UI/UX Analysis. The Full CRO path adds a technical layer and cross-references it against the visual findings.

Evaluation setup

One public demo page. Two deliberately limited runs.

I tested one B2B SaaS demonstration homepage twice: once using the Full CRO Audit and once using UI/UX Analysis. The narrow scope was deliberate. It conserved tokens while still exercising both modes and gave me a way to compare outputs against the same page.

Where the prototype was wrong

Accurate detection can still produce an overconfident verdict.

The clearest example came from the hero. PINE correctly detected template copy that conflicted with the supplied AI-workflow positioning. Manual review confirmed the mismatch. But the audited page was itself a public demonstration template, so treating the issue as a critical production failure overstated the real context.

A 21-point UI difference and 12-point UX difference on the same page means the current scores are mode-sensitive. I do not consider them stable measurements.

Product lesson: use a shared scoring rubric across modes, expose score weights and confidence, persist previous reports, and make mode comparison a first-class interaction rather than replacing report context.

Verification boundary

What still requires consultant or technical verification

PINE should label these categories as unverified until supporting evidence is available.

Metadata & schemaCanonical, Open Graph, Twitter Card and JSON-LD claims require direct source inspection.
AccessibilityAlt coverage, landmarks, skip links and contrast require code and manual checks.
PerformanceImage formats, render-blocking resources and Core Web Vitals require measured testing.
LegalConsent and privacy obligations depend on scripts, processing, geography and legal review.
Conversion impactPredicted improvements are hypotheses requiring tracking, baselines and post-change data.
Research benchmarksNamed studies and numeric claims need links to current primary sources before client use.

No accuracy percentage is claimed from this single evaluation. The evidence supports usefulness as a first pass, not autonomous decision-making.

What comes next

The limitations define the next product iteration.

Current limitations

  • Local-only working prototype
  • One page analysed per run
  • PDF export dropped from the current build
  • Switching modes replaces report context
  • Mode scores are not yet consistent
  • Some completion states can stall

Next improvements

  • Restore report-to-PDF export
  • Persist searchable audit history
  • Compare audit modes side by side
  • Standardise score weights and confidence
  • Attach source links to benchmark claims
  • Add timeout, retry and recovery states
Highest-value next featurePersistent audit history with mode switching and side-by-side comparison.

Reflection

AI did not replace the consultant. It created a faster place to begin.

PINE is useful to me as product evidence because it shows the whole loop: a recurring workflow problem, a product hypothesis, interface and state design, a working prototype, evaluation against real output, and a roadmap shaped by the failures rather than hidden from them.

The question for the next iteration is not “How can the AI sound more certain?” It is: how can an AI-assisted audit become more consistent, transparent and useful without pretending that confidence is the same as correctness?
